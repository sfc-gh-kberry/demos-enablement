The Challenge

Why You Need an AI Gateway

As teams adopt LLMs across the organization, common pain points emerge:

Fragmented Access

Every team manages their own API keys, endpoints, and SDKs. No single point of control for who calls what model.

Zero Visibility

No centralized view of token usage, latency, or cost. Teams can't answer "how much are we spending on LLMs?"

No Model Governance

Can't restrict which models are used, enforce compliance policies, or swap models without touching every application.

Credential Sprawl

API keys scattered across notebooks, apps, and CI pipelines. Rotating a key means touching dozens of configs.

The Solution

What is Cortex AI Gateway?

A centralized, OpenAI-compatible inference endpoint built into every Snowflake account.

Auto-Provisioned

One gateway per account (named SNOWFLAKE). No setup required — it's already there.

OpenAI-Compatible API

Any SDK or framework that speaks /v1/chat/completions works. Just change base_url.

Model Allowlists

Control which models are permitted with glob patterns: '*' for all, 'claude-*' to restrict.

Built-in Observability

Every call traced with OpenTelemetry — tokens, latency, payloads — queryable via SQL.

-- That's the entire setup:
ALTER AI GATEWAY SNOWFLAKE FROM SPECIFICATION $$
models:
  - name: '*'
logging:
  enabled: true
  capture_payload:
    request_response: true
$$;

MCP Server

Snowflake as a Tool Provider

The MCP server exposes Snowflake capabilities as tools — no Cortex Agent wrapper required.

ToolTypeWhat It Does
query_campaigns CORTEX_ANALYST_MESSAGE Translates natural language to SQL against the semantic view. Returns the query and interpretation.
execute_sql SYSTEM_EXECUTE_SQL Runs the generated SQL and returns actual result rows. Chained after Analyst.
search_strategy_docs CORTEX_SEARCH_SERVICE_QUERY RAG retrieval over strategy documents, methodologies, and planning briefs.
CREATE MCP SERVER MARKETING_MCP FROM SPECIFICATION $$
tools:
  - name: query_campaigns
    type: "CORTEX_ANALYST_MESSAGE"
    identifier: "CORTEX_GATEWAY_LAB.PUBLIC.CMO_ANALYTICS"
  - name: execute_sql
    type: "SYSTEM_EXECUTE_SQL"
  - name: search_strategy_docs
    type: "CORTEX_SEARCH_SERVICE_QUERY"
    identifier: "CORTEX_GATEWAY_LAB.PUBLIC.STRATEGY_SEARCH_SVC"
$$;

Clients connect via HTTP — no local bridge or npx required.

Demo

LangChain Agent in Action

Three lines to point LangChain at the gateway:

from langchain_openai import ChatOpenAI

llm = ChatOpenAI(
  model="openai-gpt-5.4",
  base_url=f"https://{ACCOUNT}/api/v2/aigateways/snowflake/v1",
  api_key=PAT_TOKEN,
)

The agent chains tools to answer data questions:

Q: "What was the ROAS by channel for Q4 2024?"

Step 1: Agent calls query_campaigns → Cortex Analyst generates SQL
Step 2: Agent calls execute_sql with the generated SQL → gets result rows
Step 3: Agent synthesizes: "Paid Search: 4.02x, Email: 12.35x, Social: 1.68x, Display: 1.34x"

Q: "How did Q4 perform against the planning brief targets?"

Agent uses both tools: query_campaigns + execute_sql for actual numbers, search_strategy_docs for the Q4 brief targets. Compares actual ROAS vs 3.5x target.

Governance

Admin Controls

Model Allowlists

Restrict which models can be called through the gateway.

models:
  - name: 'claude-*' # Only Claude models

Non-matching models get HTTP 401.

Role-Based Access

Separate inference from monitoring:

GRANT USAGE ON AI GATEWAY SNOWFLAKE
  TO ROLE AI_GATEWAY_USER;

GRANT MONITOR ON AI GATEWAY SNOWFLAKE
  TO ROLE AI_GATEWAY_MONITOR;

Usage Quotas

Set per-user credit limits with block enforcement. Exceeding the quota returns HTTP 403.

CALL quota!SET_PER_USER_LIMIT(
  1, 'DAILY'
);

Payload Capture

Record full request/response content for compliance, debugging, and audit:

logging:
  capture_payload:
    request_response: true
Summary

Key Benefits

Universal Compatibility

OpenAI-compatible API means any framework works — LangChain, LlamaIndex, OpenAI SDK, Anthropic SDK, raw HTTP. Change one URL.

Centralized Governance

One place to control model access, enforce quotas, and manage credentials. Swap models without touching application code.

Automatic Observability

Every inference call traced with tokens, latency, model metadata, and optional payload capture. Query it all with SQL.

Data Stays in Snowflake

MCP keeps the agent's tool boundary clean — it queries Snowflake data without exposing credentials or raw SQL to the LLM.

Cost Attribution

Per-model, per-user credit tracking via AI_GATEWAY_USAGE_HISTORY. Know exactly who spent what.

Zero Infrastructure

No proxy servers, no API key management, no separate observability stack. It's built into the platform.
