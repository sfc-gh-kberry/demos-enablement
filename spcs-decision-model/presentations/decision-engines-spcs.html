The Problem

Many AI workloads don't need text generation. They need fast, structured decisions over closed label sets — with calibrated confidence scores, not hallucinated prose.

Sentiment Classification

Route customer feedback to the right team based on tone. Needs to be fast enough for real-time pipelines and accurate enough to trust without human review.

Entity Resolution

Match ambiguous descriptions to canonical entities from a known set. "Apple" could be a tech company, a record label, or a farm cooperative.

Document Filtering

Score documents against arbitrary criteria: does this contain PII? Is this a financial disclosure? Binary decisions with calibrated probability.

Our Approach

Non-autoregressive decision engines that answer typed questions in a single forward pass. No text generation, nothing to parse, nothing to hallucinate.

Key insight: These models are trained as classifiers, not generators. A single forward pass produces a probability distribution over a closed label set. Inference is 10-100x faster than LLM generation, and the output is deterministic and structured.

Decision Primitives

Three typed outputs — no free-text parsing required

choice

Pick from named options. Returns the winner, full probability distribution, and confidence score.

{"sentiment": {
  "choice": "positive",
  "confidence": 0.94,
  "probabilities": {
    "positive": 0.92,
    "negative": 0.03,
    "neutral": 0.05
  }
}}

noul

Binary yes/no. Returns calibrated P(true) from 0.0 to 1.0. Threshold at 0.5 or use the raw probability.

{"relevant": {
  "noul": 0.94
}}


// P(true) = 0.94
// threshold >= 0.5 -> TRUE

score

Ordered rubric (2-10 levels). Returns expected score and per-level probability distribution.

{"urgency": {
  "score": 1.84,
  "probabilities": {
    "0": 0.05,
    "1": 0.11,
    "2": 0.84
  }
}}

The SQL Interface

One generic function — caller defines the questions

DECIDE(state VARCHAR, questions VARIANT) RETURNS VARIANT 
-- Sentiment classification
SELECT
    text,
    DECIDE(text, OBJECT_CONSTRUCT(
        'sentiment', OBJECT_CONSTRUCT(
            'type', 'choice',
            'instructions', 'Classify the sentiment.',
            'criteria', OBJECT_CONSTRUCT(
                'positive', 'positive sentiment',
                'negative', 'negative sentiment',
                'neutral', 'neutral or factual'
            )
        )
    )) AS result,
    result:sentiment:choice::VARCHAR AS sentiment,
    result:sentiment:confidence::FLOAT AS confidence
FROM reviews;
No schema changes needed to switch use cases. The same function handles sentiment, entity resolution, document filtering, urgency scoring, churn detection, and any other typed decision — just change the questions VARIANT.
